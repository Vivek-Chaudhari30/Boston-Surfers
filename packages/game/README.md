# @cb/game

Phaser runner played on riders' phones. **Owned by Jeet.**

The playable runner is implemented. It uses an original comic-book Boston city,
three tracks, low barriers (jump), overhead bars (duck), trains (change
lanes), coins, a speed ramp, and score/result callbacks. All art is drawn
with layered Phaser shapes; the game package has no external images or network requests.
The app's accompanying city tracker uses the existing MBTA API and OpenStreetMap tiles.

## Try it

Open `http://localhost:3000/dev/game` while the development server is running.
Click **LET’S ROLL!**. The canvas then has keyboard focus:

- Left/right arrows or A/D: change lanes.
- Up arrow, W, or Space: jump over yellow barriers.
- Down arrow or S: duck under pink overhead bars.
- Swipe in those same directions on a phone or trackpad-driven pointer.
- Four buttons at the bottom also control the runner.

Hitting a train always ends a run. Each course row leaves two lanes clear,
with a coin in one of the safe lanes. The first obstacle is 70 metres out
to provide time to learn the controls. **RUN IT BACK!** chooses a fresh course
in practice; ranked play obtains a fresh server run before restarting.
Line-color buttons remount with the selected accent color.

## Host integration

The course depends only on `seed`. Frame-rate differences change when
objects appear, but not their lanes, positions, types, or coin placements.
`RunnerHandle.restart(seed)` resets all run state; `destroy()` removes the
canvas/input handlers and restores scroll/touch styles. Scroll locks are
reference-counted when multiple runners are mounted.

Score is `floor(distance * GAME.SCORE_PER_METER) + coins * GAME.COIN_VALUE`.
All speed and scoring constants come from `@cb/shared`. The model ignores
large catch-up frames after suspension, caps coin density, and ends long
runs before the server's ten-minute expiry. `durationMs` measures active
simulation time. `onGameOver` reports one result per completed run.

This package never awards prizes or submits results. The parent app owns
server run IDs and must create a valid server run before every replay, or
show/navigate to its own results screen when `onGameOver` fires. Keep local
practice replays separate from ranked score submissions.

## Comic redesign

- Original hoodie/backpack runner with animated limbs, scarf, jump/duck poses and lane trails.
- Parallax clouds and skyline, shaded colorful trains, moving tracks, overhead pennants,
  spinning coins, pickup bursts, camera impact, and THWIP/SWISH/KA-CHING callouts.
- Local Impact/Arial Black typography, halftone panels, sticker buttons and comic score cards.
- Immediate score on game over, then leaderboard directly below. Solo ranked play
  displays its result before awaiting the server and labels cached standings while updating.
- Multiplayer races show personal score immediately, distinguish live positions from
  final standings, and preserve spectator results and server-owned race flow.
- Practice history stays on the current device and is explicitly labelled. No fake
  opponents or production leaderboard submissions are generated by the practice page.
- Parent UI owns results and replay; the Phaser scene no longer starts unregistered replays.
- Map changes preserve geographic placement, pan/zoom, train selection, feed fallback,
  basemap attribution and existing API adapters.
- Reduced-motion preferences suppress decorative particles, shakes and CSS entrance effects.
